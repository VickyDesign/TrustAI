# Plumb

Onboard, evaluate, release and monitor AI agents.

You onboard one agent at a time in four steps:

1. **Connect.** Plumb sends a real test request to the agent's endpoint.
2. **Describe.** You record the owner, audience, data sources and tools.
3. **Evaluate.** Plumb rates risk across 12 dimensions. It then runs accuracy, prompt-injection, PII, scope and latency suites against the live endpoint.
4. **Deploy.** Approval depends on the risk tier, then you choose a rollout.

Once an agent is live, callers send traffic through the Plumb gateway. The gateway blocks jailbreak attempts, redacts PII in both directions, and traces every request for the monitoring views.

| Part | Stack | Hosted on |
|---|---|---|
| `frontend/` | Next.js 15, React 19, TypeScript | Vercel |
| `backend/` | FastAPI, psycopg 3, httpx | Render |
| `supabase/` | Postgres schema, email and password auth | Supabase |

## Deploy

### 1. Supabase

1. Create a project at [supabase.com](https://supabase.com).
2. Create the schema. Use either method:
   - Open **SQL Editor**, paste the contents of `supabase/migrations/20261007000000_init.sql`, and run it.
   - Or, with the Supabase CLI: `supabase link --project-ref <ref>` and then `supabase db push`.
3. Under **Authentication > Sign In / Providers**, make sure Email is enabled. To let people sign in without confirming their email first, turn off "Confirm email".
4. Note down these values:
   - **Project settings > API:** the Project URL and the anon (publishable) key.
   - **Project settings > Database > Connection string > Session pooler:** the URI. Replace `[YOUR-PASSWORD]` in it.
   - **JWT secret:** only if your project still uses the legacy HS256 secret. Find it under Project settings > API > JWT settings. Projects on the newer signing keys don't need it, because the API reads the public keys from `SUPABASE_URL`.

Row Level Security is on for every table and no policies are defined. Only the backend reaches the data, using the database connection string, so the anon key can't read anything.

### 2. Render (API)

1. In Render, choose **New > Blueprint** and pick this repository. `render.yaml` creates the `plumb-api` web service from `backend/`.
2. Fill in the environment variables when Render asks for them:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Session pooler URI from Supabase |
| `SUPABASE_URL` | `https://<ref>.supabase.co` |
| `SUPABASE_JWT_SECRET` | Legacy JWT secret, or leave empty |
| `ENCRYPTION_KEY` | Generated by Render. Never change it once agents are saved. |
| `CORS_ORIGINS` | Your Vercel URL, for example `https://plumb.vercel.app` |
| `CORS_ORIGIN_REGEX` | Optional. Allows preview deployments, for example `https://plumb-.*\.vercel\.app` |
| `LLM_API_KEY` | Optional. Enables model-graded evaluations. |
| `LLM_BASE_URL`, `LLM_MODEL` | Any OpenAI-compatible Chat Completions endpoint and model |

3. Wait for the deploy to finish, then check `https://<service>.onrender.com/health`. It should return `{"ok":true}`. The gateway address uses the service URL automatically; set `PUBLIC_API_URL` only if you put a custom domain in front.

Free Render services sleep when idle, so the first request after a pause takes a few seconds. Use a paid instance for gateway traffic that needs to be fast.

### 3. Vercel (frontend)

1. Import the repository in Vercel and set **Root Directory** to `frontend`. The framework is detected as Next.js.
2. Add these environment variables:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `NEXT_PUBLIC_API_URL`: the Render URL
3. Deploy, then return to Supabase. Under **Authentication > URL Configuration**:
   - Set the Site URL to your Vercel URL.
   - Add `https://<your-app>.vercel.app/login` to Redirect URLs.
4. If you haven't already, put the Vercel URL in `CORS_ORIGINS` on Render.

### 4. First run

- **Create the workspace.** Sign up; the first sign-in creates a workspace and makes you its admin.
- **Invite people.** Under **Settings > People**, create an invite code. Teammates enter it when they sign up. Give approvers the Risk owner or Security role.
- **Create a gateway key.** Do this under **Settings > Gateway keys**. Applications call a live agent with:

```bash
curl -X POST https://<api>/v1/agents/<agent-slug>/invoke \
  -H "Authorization: Bearer plumb_..." \
  -H "Content-Type: application/json" \
  -d '{"input": "Hello", "session_id": "user-123"}'
```

## Supported agents

| Hosting | What to enter |
|---|---|
| HTTP endpoint | Any JSON POST. The request body template uses `{{prompt}}` and `{{session_id}}`. The answer is read from a dot path such as `result.answer`, or detected automatically. |
| A2A agent | The agent's base URL. Plumb reads the agent card and calls `message/send`. |
| Google ADK | The service URL plus the app name. Plumb uses `/run` with sessions. |
| Azure AI Foundry or OpenAI | A Responses API or Chat Completions URL, plus the model or deployment |
| Copilot Studio | The Direct Line URL, with the Direct Line secret as a bearer token |

Credentials can be a bearer token, an API key header, or OAuth 2.0 client credentials. They're encrypted with `ENCRYPTION_KEY` and never returned by the API. For safety, agent URLs that resolve to private or loopback addresses are refused unless `ALLOW_PRIVATE_ENDPOINTS=true`.

## Risk tiers and approvals

| Tier | Approvals before deploy |
|---|---|
| 1, low | None |
| 2, medium | Risk owner |
| 3, high | Risk owner and security |

Admins can approve anything. Under Settings, you can stop people from approving agents they submitted themselves.

## Local development

```bash
# Database: any Postgres 15+
createdb plumb && psql plumb -f supabase/migrations/20261007000000_init.sql

# API
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # set DATABASE_URL, SUPABASE_*, ENCRYPTION_KEY, ALLOW_PRIVATE_ENDPOINTS=true
uvicorn app.main:app --reload --port 8000

# Frontend
cd frontend
cp .env.example .env.local    # point NEXT_PUBLIC_API_URL at http://localhost:8000
npm install && npm run dev
```

`backend/tests/` contains a mock agent and an end-to-end test of the whole lifecycle. The test signs its own tokens with `SUPABASE_JWT_SECRET` and needs `ALLOW_PRIVATE_ENDPOINTS=true` on the API:

```bash
cd backend
uvicorn tests.mock_agent:app --port 9100 &
python tests/e2e_flow.py
```
